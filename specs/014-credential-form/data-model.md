# Data Model: Credential Form (Create & Edit)

**Feature**: [014-credential-form](spec.md) | **Consumes**: [Credential model (008)](../008-credential-data-contract/data-model.md)

## Entities

No new persistent entities. The feature introduces a transient form model that mirrors a subset
of the 008 `Credential` contract, and consumes `VaultStore` mutations unchanged.

### Form model (transient, component-local)

`CredentialFormModel` — plain object held in a `WritableSignal`, wrapped by Signal Forms'
`FieldTree`:

| Field      | Type   | Required | Maps to (008)              | Notes |
|------------|--------|----------|----------------------------|-------|
| `name`     | string | yes      | `name` (`min(1)`)          | exact zod rule — no trim |
| `username` | string | yes      | `username` (`min(1)`)      | exact zod rule |
| `domain`   | string | yes      | `domain` (`min(1)`)        | exact zod rule |
| `password` | string | yes      | `password` (`min(1)`)      | `input[type=password]`; pre-filled in edit |
| `notes`    | string | no       | `notes` (default `""`)     | textarea; empty string allowed |

Deliberately absent: `id` (store-owned on create, route-owned on edit), `favorite` (not part of
this slice — spec Assumption), `created_at`/`updated_at` (store-owned timestamps).

### Consumed entity: Credential (from 008) — unchanged

| Field        | Type    | Used by create | Used by edit |
|--------------|---------|----------------|--------------|
| `id`         | string  | — (generated by `add`) | route param → `getById`, `update` target |
| `name`       | string  | written        | prefill → written |
| `username`   | string  | written        | prefill → written |
| `domain`     | string  | written        | prefill → written |
| `password`   | string  | written        | prefill → written |
| `favorite`   | boolean | schema default (`false`) | untouched |
| `notes`      | string  | written        | prefill → written |
| `created_at` | string  | set by store   | untouched |
| `updated_at` | string? | —              | set by store on `update` |

## Route model

| URL                          | Component        | Params               | Behavior |
|------------------------------|------------------|----------------------|----------|
| `/credentials/new`           | `CredentialForm` | —                    | empty model → create mode |
| `/credentials/:id/edit`      | `CredentialForm` | `id` (signal `input()`) | known id → prefill edit mode; unknown → not-found state |
| `/` (existing, list)         | `CredentialList` | —                    | create mode's exit target |
| `/credentials/:id` (existing, detail) | `CredentialDetail` | `id`      | edit mode's exit target |

Both new routes are lazy `loadComponent` children of the dashboard shell (006), siblings of the
existing list and detail children. Static `new` outranks the `:id` parameter (research D5).

## State transitions

### Create mode

1. Route mounts → model signal initialized to empty strings; `favorite` not in model.
2. User fills fields → `FieldTree` writes flow into the model signal (single source of truth).
3. Submit → `submit(form, action)` runs the action **only if valid**:
   a. invalid → action never runs; errors surface (US3); store untouched.
   b. valid → `VaultStore.add(model())` → navigate to `/` (list renders the new entry).
4. Cancel → navigate back; no store call.

### Edit mode

1. Route mounts with `id` → `store.getById(id)`:
   - found → model prefilled from the five fields.
   - not found → not-found card; no form fields rendered (FR-012).
2. User edits → model signal updated.
3. Submit → valid: `VaultStore.update(id, model())` → navigate to `/credentials/:id`
   (detail shows updated values, `updated_at` set by the store). Invalid: no action, errors.
4. Cancel → navigate to `/credentials/:id`; no store call.
5. Entry deleted mid-edit → `getById` is signal-derived; guard flips to not-found; a submit
   reaching `update` no-ops on the missing ID (008 behavior) and navigation lands on not-found.

### Validation gate

- Field rules: `required()` on the four required fields only — deliberately identical to
  `credentialDraftSchema`'s `min(1)` semantics (whitespace-only passes both, spec edge case #1).
- Gate: `submit()`'s validity check precedes every store mutation; the store's own
  `safeParse` (007/008) remains the final boundary — by construction it never disagrees.

## Relationship map

- **VaultStore** (008) — `add(draft)`, `update(id, patch)`, `getById(id)` consumed verbatim;
  no signature changes, no new methods.
- **credential.schema** (008) — type source (`CredentialDraft`, `CredentialPatch`) and parity
  oracle for validation tests; runtime behavior unchanged.
- **CredentialList** (009) — hosts the create entry points (header + empty state).
- **CredentialDetail** (009) — hosts the edit entry point; edit mode's exit target.
- **App routes** — two new lazy children; existing routes untouched.
- No persistence, no crypto, no Supabase; `favorite` flows around this feature untouched.
